# same-page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `same-page` Claude Code plugin with five user-invoked commands (`glossary`, `check`, `translate`, `rules`, `rename`) that keep code aligned with a domain glossary, plus the merged readability + DDD doc.

**Architecture:** Prompt-only plugin. One `SKILL.md` per command, no scripts. Behavior is tested with `claude plugin eval` against a small TypeScript fixture project ("catering") that has planted drift, untested rules and an ambiguous term. Each command task adds its own eval cases first (they fail, since the skill doesn't exist yet), then writes the skill until they pass.

**Tech Stack:** Claude Code plugin format (`.claude-plugin/plugin.json`, `skills/*/SKILL.md`), `claude plugin validate`, `claude plugin eval` (llm graders, `scaffold_script`), bash, git.

**Spec:** `docs/superpowers/specs/2026-11-04-same-page-design.md`

## Global Constraints

- Plugin path: `plugins/same-page/` in repo `/Users/guillermo.schmithalter/Documents/projects/skills`.
- `plugin.json`: name `same-page`, version `0.1.0`, license `MIT`, author `Guillermo Schmithalter` / `https://github.com/schmigui-dev`, homepage `https://github.com/schmigui-dev/skills/tree/main/plugins/same-page`, repository `https://github.com/schmigui-dev/skills`.
- Every SKILL.md frontmatter: `name`, `description`, `disable-model-invocation: true`, `argument-hint`.
- Commands are namespaced `/same-page:<command>`.
- Glossary header records `**Business language:**` and `**Code language:**`. Terms are headed by the business-language name. Entry fields, in order: Code term (omit if languages match), Definition, Code names, Avoid, Not the same as, Rules, Examples, Status (`confirmed | draft`), Sources, Open questions.
- `/glossary` sources are open-ended: any business doc format (md, txt, pdf, docx, pptx, xlsx/csv, html), images, folders of docs, connected-tool pages, quoted free text, code paths, or a mix. Office files go through any available converter (`textutil`, `pandoc`, `markitdown`, unzip XML, installed docx/pptx skills). If a source can't be read, name it, ask for an export, and continue with the rest. Never guess contents. No args means the whole repo. Each run merges into the same glossary. Conflicts with confirmed entries are always asked about and never overwritten. Doc-derived terms stay `draft` until the user confirms. Grouped under `## Context: <name>`, each context opening with `**Code location:** <folders/globs>`. **Avoid** applies only within its own context.
- Existing non-standard glossary: missing fields are added only via `/same-page:glossary` with approval; until then `check`/`rename` work out code names from the definitions and say so.
- `rename` never runs migrations. Writing a migration file or alias route needs its own explicit approval.
- Glossary path default `docs/domain/glossary.md`.
- `/glossary` asks business language first, then code language (detects it if code exists, recommends English for new projects), when they aren't recorded.
- A mapped translation is never drift. A business-language identifier in a different-language codebase is **mixed-language drift**.
- Never write a glossary entry as `Status: confirmed` without the user's answer. Never edit files before showing the change and getting approval (`glossary`, `rename`). `check`, `rules`, `translate` are read-only.
- `check` default target: current uncommitted diff (staged + unstaged).
- If a glossary exists elsewhere or in another format, use it; don't migrate unless asked.
- Reports follow no-surrender style: ranked by impact, capped, with a count of what was dropped, findings as `file:line`.
- Git: repo-local `user.email` must be `gschmithalter14@gmail.com` (check before first commit). Push only via `git@github.com-personal:schmigui-dev/skills.git`, and only if the user asks.

## Review Focus

1. **No glossary in the project:** `check` and `rules` offer `/same-page:glossary` and stop. `translate` runs from code but says so. Pinned in Tasks 3, 5 and 4.
2. **Empty diff on `check`:** say so and ask what to check, with no whole-repo scan. Pinned in Task 3.
3. **Same word, different meaning** (`ShiftProposal` in staffing vs `Proposal` in proposals): `rename` must list it as "do not rename" and `check` must not call it drift. Pinned in Tasks 3 and 6.
4. **Glossary in a non-default location** (`GLOSSARY.md` at repo root): found and used, not migrated. Pinned in Task 3.
5. **Persisted names in `rename`** (SQL table, status string values): migration proposed, never applied silently. Pinned in Task 6.
